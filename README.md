# Team View

Claude Code 팀 에이전트가 **실제로 일하는 모습**을 도트 캐릭터로 보여주는 윈도우 앱.

터미널 로그 대신 사무실 한 칸을 봅니다. `frontend-dev`가 호출되면 그 캐릭터가 자기 책상으로
걸어가 앉아서 타이핑하고, 무슨 파일을 만지는지 말풍선에 뜹니다. 작업이 끝나면 자리에서 일어납니다.

> **작업으로 보이는 움직임은 전부 실제 훅 이벤트에서 나옵니다.** 없는 작업을 지어내
> 자리로 걸어가 타이핑하는 캐릭터는 없습니다.
>
> 일이 없을 때의 커피·잡담·휴게실 같은 움직임은 연출이며, **흐린 말풍선**으로 구분합니다.
> 이름표에 활동 배지(`✎ 수정 · 12s · 🛠 3`)가 붙어 있으면 그건 진짜 작업입니다.

## 다른 컴퓨터에서 처음 켤 때

**앱만 복사해서는 동작하지 않습니다.** 팀뷰는 Claude Code를 띄우고, 그 활동은 python 훅이
기록합니다. exe만 옮긴 PC에서는 화면은 떠도 아무 일도 일어나지 않는데, 무엇이 없어서인지
알 방법이 없습니다. 그래서 시작할 때 먼저 확인하고 안내합니다.

| 필요한 것 | 없으면 | 앱이 하는 일 |
|-----------|--------|--------------|
| **Node.js** | Claude Code를 설치·실행할 수 없음 | 공식 다운로드 페이지를 엽니다 |
| **Python** | **팀 활동이 화면에 안 나옵니다** (훅이 python으로 돕니다) | 공식 다운로드 페이지를 엽니다 |
| **Claude Code** | 팀원이 일하지 못함 | `npm i -g @anthropic-ai/claude-code`를 새 창에 띄웁니다 |
| Git *(선택)* | 되돌릴 수단이 없음 — 회사는 권한을 묻지 않습니다 | 공식 다운로드 페이지를 엽니다 |

> **설치는 동의를 누른 뒤에만 진행됩니다.** 무엇을 왜 넣는지, 어떤 명령이 실행되는지
> 확인 창에 그대로 보여 줍니다.
>
> 그리고 **앱이 직접 설치하지 않습니다.** npm으로 되는 것은 명령을 새 터미널에 띄워
> 무엇이 도는지 보이게 하고, 설치 프로그램이 필요한 것은 공식 페이지를 열어 주는 데서
> 멈춥니다. 설치 파일을 대신 내려받아 실행하는 순간, 앱이 무엇을 실행하는지 사람이
> 확인할 방법이 사라지기 때문입니다.

## 처음 열면

붙인 프로젝트가 없으면 사무실 자리에 **다음에 할 일**이 뜹니다 — 폴더를 고르는 버튼
하나와, 고르면 무슨 일이 일어나는지에 대한 한 문단입니다. 화면 조작(드래그로 이동,
`Ctrl`+휠로 확대, `Ctrl`+`0`으로 원래 크기)도 여기 적혀 있습니다.

> 예전에는 빈 사무실에 팀원 열한 명이 앉아 있고, 할 일은 상단 구석의 작은 배지·버튼과
> 입력창 안내문 **세 군데로 흩어져** 있었습니다. 화면에서 가장 큰 자리가 처음 열었을 때
> 가장 쓸모없었습니다.

## 쓰기 전에 — Claude 로그인과 Figma 연결

**팀뷰는 Claude Code 위에서 도는 앱입니다.** claude가 없거나 로그인이 안 돼 있으면 지시를
보내도 아무 일도 일어나지 않습니다. 기획안·화면설계서는 Figma에 만들므로 Figma 연결도
필요합니다.

상단 오른쪽에 **연결 상태 점**이 항상 켜져 있습니다. 문제가 있을 때만 보이면 "지금 연결돼
있다"는 확인을 할 수 없어서, 정상일 때도 계속 표시합니다.

| 점 | 뜻 |
|----|-----|
| 🟢 `Claude` / `Figma` | 쓸 수 있음 — 마우스를 올리면 계정·플랜이 보입니다 |
| 🟡 `Figma 미연결` / `Figma 인증 필요` | 기획안·화면설계서를 만들 수 없음 |
| 🔴 `Claude 로그아웃` / `Claude 미설치` | **지시를 보내도 처리되지 않음** |
| ⚫ 회색 | 아직 확인할 수 없음 (Claude 로그인이 먼저입니다) |

점을 누르면 — 문제가 있으면 그걸 푸는 절차로, 정상이면 상태를 다시 잽니다. 재는 동안
점이 깜빡여 멈춘 것과 구분됩니다. 앱 밖에서 로그인이 풀릴 수도 있으므로 1분마다 지켜봅니다.

여기에 더해, 빠진 게 있으면 **맨 위에 배너**로 무엇을 해야 하는지 알려줍니다.

| 상태 | 확인 방법 | 배너 버튼 |
|------|-----------|-----------|
| claude 미설치 | `claude auth status`가 명령을 못 찾음 | (설치 명령 안내) |
| 미로그인 | `claude auth status` → `loggedIn: false` | **Claude 로그인** |
| Figma 미연결 | `claude mcp list`에 figma가 없거나 `Needs authentication` | **Figma 연결** |

> 로그인 자체는 앱 창 안에서 할 수 없습니다. 둘 다 **브라우저 OAuth**라서, 버튼을 누르면
> 앱이 새 터미널 창을 열어 `claude auth login`(또는 Figma MCP 추가)을 실행합니다.
> 브라우저에서 로그인을 마치면 **앱이 30초마다 확인해 자동으로 배너를 내립니다** —
> 다시 눌러 볼 필요가 없습니다.

## 지금 무슨 상태인지 읽는 법

이름표 옆 배지가 그 팀원의 현재 상태입니다.

```
기획   ⋯ 생각 중 · 2m 5s · 🛠 3 · 조용 40s
 │         │         │       │       └ 마지막 도구를 쓴 뒤 지난 시간
 │         │         │       └ 이번 작업에서 호출한 도구 수
 │         │         └ 작업을 시작한 뒤 지난 시간
 │         └ 지금 하는 일 (✎ 수정 / ▤ 읽는 중 / ▸ 실행 / ↗ 위임 / ⌕ 검색 …)
 └ 팀원 이름
```

**`⋯ 생각 중`은 멈춘 게 아닙니다.** 모델이 답을 만드는 동안에는 도구 호출이 없어서
화면이 조용해집니다. 긴 문서를 쓸 때는 몇 분씩 이어지기도 합니다 — 그래서 조용한 시간을
같이 적고, 배지가 숨쉬듯 깜빡여 살아 있음을 보여 줍니다.

> 예전에는 마지막 이벤트로부터 2.6초가 지나면 모니터가 꺼졌습니다. 기획안을 쓰느라 2분
> 넘게 조용했던 팀원이 **노는 것처럼 보여** 멈춘 줄 알고 취소한 적이 있습니다. 지금은
> 시작과 끝 사이면 계속 일하는 중으로 그립니다.

기본 자세는 **자기 자리에 앉아 있는 것**입니다. 모니터가 켜져 있으면 일하는 중이고,
자리를 뜨는 건 커피·휴게실·잡담 같은 유휴 행동이 잡혔을 때뿐입니다.

화면은 아이소메트릭(2.5D) 도트입니다. 격자·책상·모니터는 아이소 상자로, 캐릭터는
평면 스프라이트에 그림자·외곽·측면 그늘을 얹어 입체로 보이게 했습니다.

### 끝나면 알려 줍니다

팀 작업은 20분에서 한 시간까지 갑니다. 그동안 이 창을 계속 보고 있을 수는 없어서,
**지시 하나가 끝나면** 작업표시줄이 깜빡이고 알림이 뜹니다. 알림을 누르면 그 프로젝트를
띄운 채 창이 앞으로 나옵니다 — 세 개를 붙여 놓았어도 끝난 쪽을 찾아 들어가지 않아도 됩니다.

- 창을 보고 있는 중이면 **알리지 않습니다.** 화면으로 이미 보이니까요.
- 대기 중인 지시가 더 있으면 아직 끝난 게 아니므로 알리지 않습니다. 마지막 한 건이
  끝날 때만 옵니다.
- 창을 다시 보면 깜빡임은 저절로 멎습니다.

> 창이 눈앞에 있는지는 `focus`/`blur`/`minimize` **이벤트로** 따라갑니다. `isFocused()`를
> 그때그때 물어보면 최소화해 둔 창도 `true`를 돌려주는 것을 실측으로 확인했습니다 —
> 자리를 비운 사람에게 알림이 가지 않는, 딱 그 상황에서 막히고 있었습니다. 최소화는
> `blur`를 동반하지 않는다는 것도 같이 확인해서 `minimize`를 따로 듣습니다.

## 개별 지시 보내기

캐릭터를 **클릭**하면 그 팀원에게 시킬 일을 적는 패널이 열립니다. 전달 방식은 **하나뿐**입니다 —
지시는 언제나 [회사](#회사)가 받습니다. 보내는 쪽에 고를 것이 없으므로 체크박스도 없습니다.

`.claude/team-commands.jsonl`에 한 줄이 쌓이고, 앱이 그 줄을 집어 `claude -p`로 실행합니다.
한 번에 한 건씩, 앞 작업이 끝나야 다음이 시작됩니다.

### 담당은 지정해도 다시 판단합니다

캐릭터를 클릭해 특정 팀원을 골라도, 지시는 **"이 일이 그 역할에 맞는지 먼저 판단하라"**는
단서와 함께 들어갑니다. 맞지 않으면 성격에 맞는 팀원에게 넘어갑니다.

프론트를 골라 둔 채 "기획안 플로우차트 추가"를 보냈더니 프론트 개발자가 기획서를 고치고
있었기 때문입니다. **사람이 고른 담당은 지시일 뿐 판단이 아닙니다.**

넘어가면 화면에서도 보입니다 — 원래 지목된 팀원이 맡을 팀원에게 걸어가
"이건 OO 쪽이 맞겠어요"라고 말하고, 채팅에 한 줄 남습니다. 지어낸 연출이 아니라
**앱이 보낸 상대**와 **실제로 시작한 팀원**이 다르다는 사실에서 나옵니다.

> 지금 누구에게 보내는지는 입력창과 보내기 버튼에 그대로 적힙니다("프론트에게 보내기").
> 고른 팀원 칩을 다시 누르면 전체로 돌아옵니다.

> ⚠️ **회사는 권한을 묻지 않습니다**(`--permission-mode bypassPermissions`). 파일 편집도,
> 셸 명령도, MCP 도구도 확인 없이 실행됩니다. 비대화형 세션이라 물어볼 상대가 없어서
> 그렇게 두지 않으면 일이 끝나지 않습니다 — 실제로 파일 편집만 열어 뒀더니 팀원 넷이
> 5~8분씩 돌고도 산출물이 하나도 안 남았습니다(결과를 옮기는 셸 명령과 Figma 호출이
> 통째로 막혔습니다). 자세한 이유는 `main.js`의 `PERMISSION_MODE` 주석에 있습니다.
>
> **버전 관리가 되는 폴더에만 붙이세요.** 되돌릴 수단은 권한이 아니라 git이 줍니다.
> 지켜보지 않을 작업은 보내지 마세요.
>
> 지시를 보내면 캐릭터 머리 위에 "지시 N건 대기"가 뜨고, 실제로 그 에이전트가 시작되면
> 사라집니다.

## 회사

**팀뷰는 기업체입니다.** 앱이 켜져 있으면 회사가 문을 연 것이고, 앱에서 보낸 지시는
언제나 회사가 받습니다. 따로 워커 창을 띄울 필요가 없습니다 — 앱이 곧 회사입니다.

### 프로젝트 3개까지 동시에

상단 탭으로 **최대 3개**의 프로젝트를 동시에 붙일 수 있습니다. 프로젝트마다 회사가 하나씩
열려 각자 자기 대기열을 처리합니다. 서로 간섭하지 않는 이유는 규약이 전부 프로젝트 폴더
안에 있기 때문입니다 — 클레임·대기열·이벤트가 모두 `<프로젝트>/.claude/` 아래입니다.

**사무실 화면은 한 번에 하나만 보여 줍니다.** 셋을 나란히 그리면 배율이 1/3로 떨어져 도트가
뭉개지고, 통행 격자(`layout.js`)도 사무실마다 따로 들어야 합니다. 대신 탭마다 상태 배지를
달아 **보이지 않는 회사가 지금 무엇을 하는지** 알 수 있게 했습니다.

| 배지 | 뜻 |
|------|-----|
| `처리 중` | 그 회사가 지금 지시를 실행하는 중 |
| `처리 중 +N` | 실행 중이고 뒤에 N건이 더 쌓여 있음 |
| `대기 N건` | 아직 시작 못 한 지시가 N건 |
| `닫힘` | `.claude`가 없어 회사를 못 엶 — **보낸 지시가 처리되지 않습니다** |
| `점유됨` | 다른 앱 창이 그 프로젝트를 맡고 있음 |
| `훅 없음` | 훅이 settings에 등록되지 않음 — **팀 활동이 화면에 안 나옵니다** |
| `팀원 없음` | `.claude/agents/`가 비어 있음 — **리드가 혼자 다 합니다** |
| `지침 없음` | `CLAUDE.md`가 없음 — 어떤 일이 누구 몫인지 리드가 모릅니다 |

### 빠졌으면 앱이 채워 줍니다

`+ 프로젝트`로 붙일 때 위 셋 중 빠진 게 있으면 **무엇이 없는지 보여주고 넣을지 묻습니다.**
상단 **세팅하기** 버튼으로 나중에 넣어도 됩니다(구성이 빠졌을 때만 나타납니다).

넣는 것은 팀뷰가 들고 다니는 템플릿(`templates/`)입니다 — 캐릭터 명단(`ROSTER`)과 같은
저장소에 있어서 **화면의 팀원과 실제 에이전트가 어긋나지 않습니다.**

| 넣는 것 | 내용 |
|---------|------|
| 훅 | `hooks/team_events.py` 복사 + `settings.json`에 6개 이벤트 등록 |
| 팀원 | `.claude/agents/`에 9명 (기획·디자인·프론트·백엔드·모바일·리뷰·QA·디버거·릴리스) |
| 지침 | `CLAUDE.md` 골격 — 담당 배분표가 들어갑니다 |

**기획안과 화면설계서는 Figma에 만듭니다.** `planner`와 `ux-designer` 모두 Figma 도구를
갖고 있고, 마크다운으로 대신하지 말라고 지시받습니다. Figma가 연결돼 있지 않으면 그리지
않고 그 사실을 보고합니다 — 글로만 남은 기획안은 결국 아무도 안 보기 때문입니다.

> **기존 설정을 덮어쓰지 않습니다.** `settings.json`에 이미 다른 훅(포매터·시크릿 가드 등)이
> 있으면 그대로 두고 team_events만 덧붙입니다. 이미 있는 파일도 건드리지 않습니다.
> 두 번 눌러도 중복되지 않습니다.
>
> `CLAUDE.md`의 **개요·스택·명령어는 비어 있습니다.** 프로젝트마다 다르니 직접 채우세요 —
> 비어 있으면 팀이 매 지시마다 프로젝트를 처음부터 훑느라 시간을 씁니다.

뒤의 셋은 **붙일 프로젝트의 준비 상태**입니다. 셋 중 하나라도 빠지면 지시를 보내도 원하는
대로 움직이지 않는데, 예전에는 **보내보고 안 움직여야** 알 수 있었습니다. 어떤 프로젝트는
훅만 깔려 있고 팀원이 없어 리드가 혼자 일했고, 그걸 알아내려고 이벤트 로그를 집계해야
했습니다. 이제 붙이는 순간 탭에 뜹니다 — 탭에 마우스를 올리면 넷 다 한 번에 보입니다.

> 배지는 한 칸이라 **진행 중이면 진행을, 조용하면 왜 조용한지**를 보여줍니다.
> 일하는 중에 `팀원 없음`이 떠서 지금 상태를 가리지 않게 한 것입니다.

탭을 옮겨도 나머지 회사는 계속 일합니다. 화면만 바뀔 뿐입니다. 옮기면 그 프로젝트의 로그를
처음부터 다시 읽어 지금 모습을 복원하고, 대화 기록도 프로젝트별로 따로 보관했다가 되살립니다.

### 세션을 고정해 이어 씁니다

프로젝트마다 세션 id(UUID)를 하나 정해 두고 계속 그 세션으로 실행합니다(앱 설정의 `sessions`).
매번 새 세션이면 그때마다 프로젝트를 처음부터 읽습니다 — 실측으로 `README`·`package.json`·
`src/*` 전부를 읽는 데만 **매 지시 15초**가 들었고, 지시 사이에 아무것도 기억하지 못했습니다.

`--continue`를 쓰지 않는 이유는 그게 **"그 폴더의 가장 최근 대화"**를 잇기 때문입니다.
사람이 같은 폴더에서 따로 claude를 띄워 두면 **그 대화를 물어 갑니다.** id를 고정하면
회사는 자기 세션만 잇습니다.

> 세션을 이으면 이전 지시의 맥락이 남아 하던 일을 계속하려 합니다. 실제로 "프로젝트
> 소개해줘"를 보냈는데 직전에 짜던 테스트 스위트를 계속 만든 적이 있습니다. 그래서 매
> 지시 앞에 **"앞의 대화는 끝난 일이다. 이어서 계속하지 마라"**는 경계를 붙입니다.

> **지시·취소는 지금 보고 있는 프로젝트에만 적용됩니다.** "작업 취소"는 그 프로젝트의 회사만
> 멈춥니다 — 다른 탭에서 돌던 작업은 건드리지 않습니다.
>
> 탭의 `×`로 프로젝트를 떼면 그 회사는 문을 닫고 **진행 중이던 작업도 중단**됩니다. 작업이
> 돌고 있으면 한 번 확인을 받습니다.
>
> 3개까지로 제한한 이유는 화면이 아니라 **비용**입니다. 회사 하나가 `claude`를 하나씩
> 띄우므로 3개면 claude가 3개 동시에 돕니다(토큰도 3배).

| 하는 일 | 어떻게 |
|---------|--------|
| 대기열 소유 | `.claude/team-worker.json`에 `mode: "poller"` 클레임을 적고 **30초마다 갱신** |
| 지시 실행 | 큐에서 한 건씩 꺼내 `claude -p`로 실행. **프로젝트마다 세션 하나를 고정해 계속 이어 씁니다** |
| 팀원 표시 | 자식 세션에 `TEAMVIEW_POLLER`를 실어 보내 훅이 그 활동만 기록 |
| 문 닫기 | 앱을 끄면 클레임을 지우고 **실행 중이던 일도 멈춥니다** |

### 왜 이렇게 바뀌었나

예전에는 지시를 처리할 주체를 사람이 골랐습니다 — 체크박스를 끄면 대기열에 쌓이고, 그걸
**그때 마침 턴을 끝내는 아무 세션**이 `Stop` 훅에서 집어갔습니다. 그래서 사람과 대화하던
세션이 앱 지시를 받아, 대화 중간에 엉뚱한 작업이 끼어들고 그 세션의 도구 호출이 전부 팀뷰
화면에 찍혔습니다.

막으라고 둔 것이 워커 클레임이었는데, 클레임 갱신이 **훅이 돌 때만** 일어났습니다. 워커가
조용히 대기하면 훅이 안 돌아 10분 뒤 클레임이 만료되고, 훅의 마지막 폴백("아무 세션이나
처리한다")으로 떨어졌습니다. 살아 있는 워커를 띄워 두고도 분리가 풀린 겁니다.

이제 클레임을 **앱이** 적습니다. 앱은 대화를 하지 않으니 조용해질 일이 없고, 타이머로 확실히
갱신합니다. 회사가 열려 있는 한 지시는 회사 것이고, 사람이 쓰는 세션에는 새어 들어가지
않습니다.

> `.claude` 폴더가 없는 프로젝트에서는 회사가 열리지 않습니다(지시를 적어도 읽을 주체가
> 없기 때문). 그때는 상태줄이 **"회사가 닫혀 있습니다 — 보낸 지시가 처리되지 않습니다"**로
> 경고합니다. 회사가 닫힌 것과 그냥 조용한 것은 화면에서 구분되지 않아서, 지시가 안 먹히는
> 걸 세 시간 동안 못 알아챈 적이 있습니다.
>
> **팀뷰는 한 번에 하나만 뜹니다.** 앱 하나가 프로젝트를 셋까지 다루므로 창을 여러 개
> 띄울 이유가 없고, 두 개가 뜨면 조용히 망가집니다 — 둘 다 자기가 회사라고 믿고 같은
> 대기열을 집어가 **같은 지시가 두 번 실행될 수 있습니다.** 설정·대화 기록·세션 id도
> 한 벌뿐이라 서로 덮어씁니다. 이미 떠 있을 때 다시 실행하면 그 창이 앞으로 나옵니다.
>
> 상태 점의 **"점유됨"**은 그래도 남겨 뒀습니다. 예전 방식의 워커 세션이나 다른
> 컴퓨터가 그 프로젝트의 클레임을 쥐고 있을 수 있기 때문입니다.

## 작업 취소

**작업 취소** 버튼은 세 가지를 한꺼번에 합니다.

| 대상 | 방법 |
|------|------|
| 아직 안 집어간 대기열 | `team-commands.jsonl`을 지웁니다 |
| 앱이 띄운 `claude -p` | 프로세스를 종료합니다 |
| **이미 돌고 있는 세션** | `.claude/team-cancel.flag`를 세웁니다 |

세 번째가 핵심입니다. 밖에서 남의 세션을 죽일 수는 없지만, `PreToolUse` 훅이 이 깃발을
보면 **다음 도구 호출을 deny** 합니다 — 에이전트는 도구를 못 쓰고, 이유를 읽고 멈춥니다.
깃발은 그 세션이 턴을 마칠 때(`Stop`) 내려갑니다. 눌러 놓고 잊어도 **5분 뒤 자동으로
만료**되므로 다음 작업을 잡아먹지 않습니다.

> 취소는 **다음 도구 호출 시점**에 걸립니다. 지금 돌고 있는 도구 하나(긴 빌드 등)는
> 끝까지 갑니다. 즉시 끊어야 하면 그 터미널에서 Esc를 누르세요.

## 빠르게 보기 (훅 없이)

```bash
pnpm install
pnpm dev
```
창이 뜨면 **+ 프로젝트**로 `.claude/`가 있는 폴더를 붙이고, 다른 터미널에서:
```bash
node tools/emit-demo-events.js <그 폴더 경로>
```
가짜 시나리오(기획→디자인→프론트→리뷰→QA)가 25초간 흐릅니다. 실제 훅과 같은 형식이라
앱 입장에선 구분되지 않습니다 — 데모가 잘 돈다고 훅 연동이 된 건 아닙니다.

## 실제 연동 (훅 설치)

보고 싶은 프로젝트에 훅을 답니다.

1. `hooks/team_events.py`를 그 프로젝트의 `.claude/hooks/`로 복사합니다.
2. 그 프로젝트의 `.claude/settings.json`(공유) 또는 `settings.local.json`(나만)에 추가:

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "*", "hooks": [{ "type": "command", "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/team_events.py\" pre", "timeout": 10 }] }
    ],
    "PostToolUse": [
      { "matcher": "*", "hooks": [{ "type": "command", "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/team_events.py\" post", "timeout": 10 }] }
    ],
    "SubagentStop": [
      { "hooks": [{ "type": "command", "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/team_events.py\" subagent_stop", "timeout": 10 }] }
    ],
    "UserPromptSubmit": [
      { "hooks": [{ "type": "command", "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/team_events.py\" prompt", "timeout": 10 }] }
    ],
    "Stop": [
      { "hooks": [{ "type": "command", "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/team_events.py\" stop", "timeout": 10 }] }
    ]
  }
}
```

3. **Claude Code를 재시작**합니다(훅은 시작할 때 읽힙니다).
4. 앱의 **+ 프로젝트**로 그 폴더를 붙입니다. 끝. (최대 3개까지 동시에)

`.claude/team-events.jsonl`, `.claude/team-events.state.json`, `.claude/team-commands.jsonl`,
`.claude/team-cancel.flag`, `.claude/team-worker.json`이 생깁니다. **`.gitignore`에
추가하세요** — 작업 기록이라 커밋할 이유가 없습니다.

`Stop` 훅은 세션이 쉬는 상태가 됐다고 알립니다. 대기열은 건드리지 않습니다 — 살아 있는
회사 클레임이 있으면 훅은 큐에서 손을 뗍니다(같은 지시가 두 번 실행되면 안 되니까).
회사가 닫혀 있을 때만 예전처럼 `{"decision":"block","reason":"…"}`으로 그 세션이 이어서
처리합니다. 회사를 안 여는 사람까지 먹통이 되면 안 되기 때문입니다.

## 알아둘 것

- **에이전트 귀속은 페이로드가 알려주는 사실입니다.** 서브에이전트가 부른 도구에는
  `agent_type`(명단 id)이 실려 오고, 리드가 부른 도구에는 그 키가 없습니다. 그대로 붙이므로
  **여러 팀원이 동시에 돌아도 각자에게 정확히 귀속됩니다.** (예전에는 `Task` 호출로 시작을
  잡고 가장 최근 에이전트에게 붙이는 추정이었고, 동시 실행에서 틀렸습니다.)
  단, `agent_type`을 보내지 않는 구버전 Claude Code에서는 모든 도구가 리드에게 붙습니다.
- **도구 호출마다 파이썬 프로세스가 하나 뜹니다.** 호출당 수십 ms가 더해집니다. 느껴지면
  `PreToolUse` 훅을 빼고 `PostToolUse`/`SubagentStop`만 남기세요. 누가 언제 시작하고
  끝났는지와 실패는 그대로 보입니다(시작은 `PostToolUse`에서도 잡습니다). 대신 도구 단위
  진행 상황은 보이지 않습니다.
- 훅은 **무슨 일이 있어도 exit 0**입니다. 시각화가 개발을 막지 않습니다.
- Bash 명령에서 키처럼 보이는 문자열이 발견되면 그 명령은 기록하지 않습니다(로그가 유출
  경로가 되지 않도록). 다만 완전하지 않으니 이 파일을 공유하지 마세요.
- 이벤트 로그가 512KB를 넘으면 새로 시작합니다. 앱이 잘림을 감지해 화면을 리셋합니다.

## 구조

```
main.js              Electron 메인 — 창 + 이벤트 파일 tail(폴링)
preload.js           렌더러에 노출하는 최소 API
renderer/
  index.html         화면 뼈대 (외부 리소스 없음, CSP 적용) + 지시 패널
  app.js             렌더 루프 + 이벤트→행동 매핑 + 클릭/지시 전송
  iso.js             아이소메트릭 좌표계·타일·상자·그림자
  sprites.js         도트 캐릭터를 코드로 찍는다 (에셋 파일 없음)
  agents.js          팀 명단·자리 배치(격자 좌표)·팔레트
  room.js            사무실 바닥·벽·창문 + 소품 목록(PROPS)
  furniture.js       책상·의자·소파·가전을 픽셀로 찍는다
  layout.js          방 구획·문 + **통행 격자**(가구를 피해 가는 길 찾기)
hooks/team_events.py Claude Code 훅 → 이벤트 기록기
tools/emit-demo-events.js  훅 없이 화면만 확인할 때
tools/check-refs.js  끊긴 참조·문법 오류를 실행 전에 잡는다
tools/check-nav.js   갈 수 있어야 할 곳에 실제로 길이 있는지 확인한다
```

캐릭터를 추가하거나 색을 바꾸려면 `renderer/agents.js`의 `ROSTER`만 건드리면 됩니다.
명단에 없는 이름이 이벤트로 들어와도 회색 캐릭터로 자리를 만들어 줍니다(무시하지 않습니다).

### 가구를 옮기거나 추가할 때

소품은 `room.js`의 `PROPS`에 좌표와 함께 **`w`·`d`(차지하는 바닥 넓이)** 를 적습니다.
경로 탐색이 이 값을 보고 돌아갑니다 — 안 적으면 캐릭터가 그 물건을 뚫고 지나갑니다.
러그처럼 밟고 지나가는 것은 비워 둡니다.

```js
{ gx: 8.6, gy: 12.4, draw: drawVending, w: 0.42, d: 0.32 },
```

`pnpm run check`가 **모든 자리와 목적지에 길이 있는지, 경로가 가구를 관통하지 않는지**
확인합니다. 가구 하나를 키웠다가 방이 통째로 고립되면 화면에서는 "그 사람만 안 움직인다"로
보여 원인을 찾기 어렵습니다. `pnpm dev`가 실행 전에 자동으로 돌립니다.

## exe로 만들기

```bash
pnpm run build:dir   # release/win-unpacked/Team View.exe  (빠른 확인용)
pnpm run build:win   # 설치본 + 포터블 exe
```
- `release/TeamView-Setup-<버전>-x64.exe` — 설치 경로를 고를 수 있는 설치본
- `release/TeamView-Portable-<버전>-x64.exe` — 설치 없이 바로 실행

> **서명 단계는 꺼져 있습니다**(`signAndEditExecutable: false`). 켜면 electron-builder가
> winCodeSign 캐시를 푸는데, 그 안에 macOS 심볼릭 링크가 있어 **Windows 개발자 모드가
> 꺼져 있으면 압축 해제가 실패**합니다. 서명할 인증서도 없으므로 껐습니다. 대신 exe의
> 아이콘·제품 정보가 기본값(Electron)으로 남습니다. 개발자 모드를 켜면 다시 켜도 됩니다.
