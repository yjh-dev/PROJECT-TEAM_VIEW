# Team View

Claude Code 팀 에이전트가 **실제로 일하는 모습**을 도트 캐릭터로 보여주는 윈도우 앱.

터미널 로그 대신 사무실 한 칸을 봅니다. `frontend-dev`가 호출되면 그 캐릭터가 자기 책상으로
걸어가 앉아서 타이핑하고, 무슨 파일을 만지는지 말풍선에 뜹니다. 작업이 끝나면 자리에서 일어납니다.

> **작업으로 보이는 움직임은 전부 실제 훅 이벤트에서 나옵니다.** 없는 작업을 지어내
> 자리로 걸어가 타이핑하는 캐릭터는 없습니다.
>
> 일이 없을 때의 커피·잡담·휴게실 같은 움직임은 연출이며, **흐린 말풍선**으로 구분합니다.
> 이름표에 활동 배지(`✎ 수정 · 12s · 🛠 3`)가 붙어 있으면 그건 진짜 작업입니다.

기본 자세는 **자기 자리에 앉아 있는 것**입니다. 모니터가 켜져 있으면 일하는 중이고,
자리를 뜨는 건 커피·휴게실·잡담 같은 유휴 행동이 잡혔을 때뿐입니다.

화면은 아이소메트릭(2.5D) 도트입니다. 격자·책상·모니터는 아이소 상자로, 캐릭터는
평면 스프라이트에 그림자·외곽·측면 그늘을 얹어 입체로 보이게 했습니다.

## 개별 지시 보내기

캐릭터를 **클릭**하면 그 팀원에게 시킬 일을 적는 패널이 열립니다. 전달 방식은 두 가지입니다.

| 방식 | 동작 | 언제 쓰나 |
|------|------|-----------|
| **대기열** (기본) | `.claude/team-commands.jsonl`에 쌓아두고, [워커 세션](#워커-세션-띄우기)이 한 턴을 마칠 때(`Stop` 훅) 그 세션에 밀어 넣습니다 | 이미 Claude Code를 켜놓고 작업 중일 때 |
| **새 세션으로 즉시 실행** (체크박스) | `claude -p "<agent> 서브에이전트로: ..."`를 새 프로세스로 띄웁니다 | 세션이 꺼져 있거나 따로 돌리고 싶을 때 |

### 담당은 지정해도 다시 판단합니다

캐릭터를 클릭해 특정 팀원을 골라도, 지시는 **"이 일이 그 역할에 맞는지 먼저 판단하라"**는
단서와 함께 들어갑니다. 맞지 않으면 성격에 맞는 팀원에게 넘어갑니다.

프론트를 골라 둔 채 "기획안 플로우차트 추가"를 보냈더니 프론트 개발자가 기획서를 고치고
있었기 때문입니다. **사람이 고른 담당은 지시일 뿐 판단이 아닙니다.**

넘어가면 화면에서도 보입니다 — 원래 지목된 팀원이 맡을 팀원에게 걸어가
"이건 OO 쪽이 맞겠어요"라고 말하고, 채팅에 한 줄 남습니다. 지어낸 연출이 아니라
**앱이 보낸 상대**와 **실제로 시작한 팀원**이 다르다는 사실에서 나옵니다.

> 지금 누구에게 보내는지는 입력창과 보내기 버튼에 그대로 적힙니다("프론트에게 보내기").
> 고른 팀원 칩을 다시 누르면 전체로 돌아옵니다.

> ⚠️ 즉시 실행은 **자율적으로 파일을 고칠 수 있는 프로세스를 띄우는 것**입니다. 그래서
> 기본값은 꺼져 있고 체크할 때만 실행됩니다. 대기열 방식은 사람이 보고 있는 세션에
> 지시가 들어가므로 그쪽이 더 안전합니다.
>
> 대기열은 `Stop` 훅이 설치돼 있어야 동작합니다(아래 설치 참고). 지시를 보내면 캐릭터
> 머리 위에 "지시 N건 대기"가 뜨고, 실제로 그 에이전트가 시작되면 사라집니다.

## 워커 세션 띄우기

앱이 보낸 지시는 **`TEAMVIEW_WORKER=1`로 띄운 세션**이 처리하게 하세요. 사람과 대화하는
세션과 앱 작업을 한 창에서 하면 세 가지가 한꺼번에 무너집니다. 대화 중이라 턴이 길면 앱
지시는 그동안 쌓이기만 하고, 지시가 사람과의 대화 사이에 끼어들어 섞이고, 그 세션에서 사람이
시킨 도구 호출이 전부 팀뷰 화면에 찍혀 **아무도 일을 안 시켰는데 리드가 계속 일하는 것처럼**
보입니다. 창을 나누면 앱은 워커만 보고, 대화 창은 조용해집니다.

```powershell
tools\worker.ps1 C:\dev\2026\PROJECT-TEMPLATE
```

그 폴더로 이동해 `TEAMVIEW_WORKER=1`을 세우고 `claude`를 띄웁니다(뒤에 붙인 인자는 그대로
넘어갑니다). 워커 세션은 훅이 불릴 때마다 `.claude/team-worker.json`에 자기 `session_id`를
적어 두고(30초에 한 번만 씁니다), 다른 세션의 훅은 그 클레임을 보고 **조용히 빠집니다** —
기록도 대기열도 취소 깃발도 건드리지 않습니다.

> **워커를 안 띄워도 지금까지처럼 동작합니다.** 클레임 파일이 없으면 아무 세션이나
> 처리합니다. 워커가 꺼져 클레임이 10분 넘게 낡으면 마찬가지로 아무 세션이나 처리합니다 —
> 워커가 죽었다고 앱이 영영 먹통이 되면 안 되기 때문입니다.

한 번이라도 워커가 있었는데 지금 죽어 있으면 상단 상태줄이 **"워커 없음 — 보낸 지시가
처리되지 않습니다"**로 경고합니다. 워커가 꺼진 것과 그냥 조용한 것은 화면에서 구분되지
않아서, 지시가 안 먹히는 걸 세 시간 동안 못 알아챈 적이 있습니다.

## 작업 취소

**작업 취소** 버튼은 세 가지를 한꺼번에 합니다.

| 대상 | 방법 |
|------|------|
| 아직 안 집어간 대기열 | `team-commands.jsonl`을 지웁니다 |
| 앱이 띄운 `claude -p` | 프로세스를 종료합니다 |
| **이미 돌고 있는 세션** | `.claude/team-cancel.flag`를 세웁니다 |

세 번째가 핵심입니다. 밖에서 남의 세션을 죽일 수는 없지만, `PreToolUse` 훅이 이 깃발을
보면 **다음 도구 호출을 deny** 합니다 — 에이전트는 도구를 못 쓰고, 이유를 읽고 멈춥니다.
깃발은 그 세션이 턴을 마칠 때(`Stop`) 내려갑니다. 눌러 놓고 잊어도 **5분 뒤 자동으로
만료**되므로 다음 작업을 잡아먹지 않습니다.

> 취소는 **다음 도구 호출 시점**에 걸립니다. 지금 돌고 있는 도구 하나(긴 빌드 등)는
> 끝까지 갑니다. 즉시 끊어야 하면 그 터미널에서 Esc를 누르세요.

## 빠르게 보기 (훅 없이)

```bash
pnpm install
pnpm dev
```
창이 뜨면 **프로젝트 선택**으로 `.claude/`가 있는 폴더를 고르고, 다른 터미널에서:
```bash
node tools/emit-demo-events.js <그 폴더 경로>
```
가짜 시나리오(기획→디자인→프론트→리뷰→QA)가 25초간 흐릅니다. 실제 훅과 같은 형식이라
앱 입장에선 구분되지 않습니다 — 데모가 잘 돈다고 훅 연동이 된 건 아닙니다.

## 실제 연동 (훅 설치)

보고 싶은 프로젝트에 훅을 답니다.

1. `hooks/team_events.py`를 그 프로젝트의 `.claude/hooks/`로 복사합니다.
2. 그 프로젝트의 `.claude/settings.json`(공유) 또는 `settings.local.json`(나만)에 추가:

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "*", "hooks": [{ "type": "command", "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/team_events.py\" pre", "timeout": 10 }] }
    ],
    "PostToolUse": [
      { "matcher": "*", "hooks": [{ "type": "command", "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/team_events.py\" post", "timeout": 10 }] }
    ],
    "SubagentStop": [
      { "hooks": [{ "type": "command", "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/team_events.py\" subagent_stop", "timeout": 10 }] }
    ],
    "UserPromptSubmit": [
      { "hooks": [{ "type": "command", "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/team_events.py\" prompt", "timeout": 10 }] }
    ],
    "Stop": [
      { "hooks": [{ "type": "command", "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/team_events.py\" stop", "timeout": 10 }] }
    ]
  }
}
```

3. **Claude Code를 재시작**합니다(훅은 시작할 때 읽힙니다).
4. 앱에서 그 프로젝트 폴더를 선택합니다. 끝.

`.claude/team-events.jsonl`, `.claude/team-events.state.json`, `.claude/team-commands.jsonl`,
`.claude/team-cancel.flag`, `.claude/team-worker.json`이 생깁니다. **`.gitignore`에
추가하세요** — 작업 기록이라 커밋할 이유가 없습니다.

`Stop` 훅은 두 가지 일을 합니다: 세션이 쉬는 상태가 됐다고 알리고, 앱에서 보낸 지시가
쌓여 있으면 `{"decision":"block","reason":"…"}`을 반환해 **그 세션이 이어서 처리하게** 합니다.

훅을 설치했으면 이어서 [워커 세션 띄우기](#워커-세션-띄우기)로 앱 전용 창을 하나 여세요.

## 알아둘 것

- **에이전트 귀속은 페이로드가 알려주는 사실입니다.** 서브에이전트가 부른 도구에는
  `agent_type`(명단 id)이 실려 오고, 리드가 부른 도구에는 그 키가 없습니다. 그대로 붙이므로
  **여러 팀원이 동시에 돌아도 각자에게 정확히 귀속됩니다.** (예전에는 `Task` 호출로 시작을
  잡고 가장 최근 에이전트에게 붙이는 추정이었고, 동시 실행에서 틀렸습니다.)
  단, `agent_type`을 보내지 않는 구버전 Claude Code에서는 모든 도구가 리드에게 붙습니다.
- **도구 호출마다 파이썬 프로세스가 하나 뜹니다.** 호출당 수십 ms가 더해집니다. 느껴지면
  `PreToolUse` 훅을 빼고 `PostToolUse`/`SubagentStop`만 남기세요. 누가 언제 시작하고
  끝났는지와 실패는 그대로 보입니다(시작은 `PostToolUse`에서도 잡습니다). 대신 도구 단위
  진행 상황은 보이지 않습니다.
- 훅은 **무슨 일이 있어도 exit 0**입니다. 시각화가 개발을 막지 않습니다.
- Bash 명령에서 키처럼 보이는 문자열이 발견되면 그 명령은 기록하지 않습니다(로그가 유출
  경로가 되지 않도록). 다만 완전하지 않으니 이 파일을 공유하지 마세요.
- 이벤트 로그가 512KB를 넘으면 새로 시작합니다. 앱이 잘림을 감지해 화면을 리셋합니다.

## 구조

```
main.js              Electron 메인 — 창 + 이벤트 파일 tail(폴링)
preload.js           렌더러에 노출하는 최소 API
renderer/
  index.html         화면 뼈대 (외부 리소스 없음, CSP 적용) + 지시 패널
  app.js             렌더 루프 + 이벤트→행동 매핑 + 클릭/지시 전송
  iso.js             아이소메트릭 좌표계·타일·상자·그림자
  sprites.js         도트 캐릭터를 코드로 찍는다 (에셋 파일 없음)
  agents.js          팀 명단·자리 배치(격자 좌표)·팔레트
  room.js            사무실 바닥·벽·창문 + 소품 목록(PROPS)
  furniture.js       책상·의자·소파·가전을 픽셀로 찍는다
  layout.js          방 구획·문 + **통행 격자**(가구를 피해 가는 길 찾기)
hooks/team_events.py Claude Code 훅 → 이벤트 기록기
tools/worker.ps1     앱 전용 워커 세션을 띄운다 (TEAMVIEW_WORKER=1)
tools/emit-demo-events.js  훅 없이 화면만 확인할 때
tools/check-refs.js  끊긴 참조·문법 오류를 실행 전에 잡는다
tools/check-nav.js   갈 수 있어야 할 곳에 실제로 길이 있는지 확인한다
```

캐릭터를 추가하거나 색을 바꾸려면 `renderer/agents.js`의 `ROSTER`만 건드리면 됩니다.
명단에 없는 이름이 이벤트로 들어와도 회색 캐릭터로 자리를 만들어 줍니다(무시하지 않습니다).

### 가구를 옮기거나 추가할 때

소품은 `room.js`의 `PROPS`에 좌표와 함께 **`w`·`d`(차지하는 바닥 넓이)** 를 적습니다.
경로 탐색이 이 값을 보고 돌아갑니다 — 안 적으면 캐릭터가 그 물건을 뚫고 지나갑니다.
러그처럼 밟고 지나가는 것은 비워 둡니다.

```js
{ gx: 8.6, gy: 12.4, draw: drawVending, w: 0.42, d: 0.32 },
```

`pnpm run check`가 **모든 자리와 목적지에 길이 있는지, 경로가 가구를 관통하지 않는지**
확인합니다. 가구 하나를 키웠다가 방이 통째로 고립되면 화면에서는 "그 사람만 안 움직인다"로
보여 원인을 찾기 어렵습니다. `pnpm dev`가 실행 전에 자동으로 돌립니다.

## exe로 만들기

```bash
pnpm run build:dir   # release/win-unpacked/Team View.exe  (빠른 확인용)
pnpm run build:win   # 설치본 + 포터블 exe
```
- `release/TeamView-Setup-<버전>-x64.exe` — 설치 경로를 고를 수 있는 설치본
- `release/TeamView-Portable-<버전>-x64.exe` — 설치 없이 바로 실행

> **서명 단계는 꺼져 있습니다**(`signAndEditExecutable: false`). 켜면 electron-builder가
> winCodeSign 캐시를 푸는데, 그 안에 macOS 심볼릭 링크가 있어 **Windows 개발자 모드가
> 꺼져 있으면 압축 해제가 실패**합니다. 서명할 인증서도 없으므로 껐습니다. 대신 exe의
> 아이콘·제품 정보가 기본값(Electron)으로 남습니다. 개발자 모드를 켜면 다시 켜도 됩니다.
