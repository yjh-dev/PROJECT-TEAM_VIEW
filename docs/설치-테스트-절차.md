# 윤사무실 설치 테스트 절차서

**읽는 사람: 이 저장소의 개발자 본인.** 비개발자용이 아니다(그건 `docs/설치안내.md`다).

깨끗한 Windows에서 **사람이 직접 따라 하며** 설치본을 처음부터 끝까지 밟는 절차다.
지금 이 저장소에서 설치 경로에 대해 검증된 것은 **논리 검사·화면 검사·스텁**뿐이다.
개발 PC에는 Python 3.13.14와 Claude Code가 이미 있어서 첫 실행 마법사가 "있음"으로 판정하고
**설치를 통째로 건너뛴다.** 즉 winget이 실제로 무엇을 깔고, UAC 창이 어떻게 뜨고, 실패하면
화면이 뭐라고 하는지는 **아무도 본 적이 없다.**

남의 PC에서 처음 돌리는 것이 실전 첫 시도가 되면 안 된다.

이 문서 안에서 쓰는 표시:

- **[코드]** — 코드에서 확인한 사실. 파일·근거를 함께 적었다.
- **[미확인]** — 코드로는 알 수 없고 이번 테스트로 확인해야 하는 것(OS 화면, 외부 도구 출력).
- **[위험]** — 코드를 읽다가 "여기서 어긋날 것 같다"고 본 자리. 반드시 실제 문구를 받아 적을 것.

| 무엇 | 어디까지 | 근거 |
|------|----------|------|
| 설치 로직(무인 플래그 4개, 타임아웃 근거, 진행 타이머, killTree, 포터블 PATH 수리 규칙) | 자동 검사 통과 | `tools/check-logic.js`가 `install.js` **원본을 그대로 require해서** 돌린다 |

| **실제 winget 설치** | **미검증** | 개발 PC는 전부 "있음"이라 실행 자체가 안 됨 |

| **PATH 영속(`persistUserPath`)이 다음 실행에서 살아 있는가** | **미검증** | 새로 깔린 것이 없으니 확인할 수 없었음 |

이 문서는 아래 것들을 사람이 직접 확인하기 위한 절차다.

## 1. 전제 조건 — 시작 전에 반드시

### 1.1 Claude 계정과 **유료 플랜(또는 API 크레딧)**

**이게 없으면 설치가 전부 끝나고 로그인까지 성공해도 지시가 아무 일도 하지 않는다.**
앱은 그 상태를 실패 분류로 잡아서 화면에 이렇게 적는다.

- `결제·크레딧 문제` / 힌트 `Claude 계정의 결제 상태를 확인하세요.` — **[코드]** `main.js:3617`
- `토큰 사용량 한도` / 힌트 `한도가 풀린 뒤 같은 지시를 다시 보내면 됩니다.` — **[코드]** `main.js:3611-3614`

즉 T-14(첫 지시)까지 가려면 **결제된 계정**이 필요하다. 테스트 계정은 다음 중 하나로 정하고
기록지 맨 위에 어느 것을 썼는지 적어 둔다.

- (권장) 평소 쓰는 본인 계정 — 대신 **테스트가 끝나면 VM을 스냅샷으로 되돌리거나 폐기해서
  자격 증명을 남기지 않는다.** VM에 로그인하면 토큰이 그 VM에 남는다.
- 전용 테스트 계정 — 결제를 따로 붙여야 하므로 준비 시간이 든다. 무료 계정으로는 T-14가
  반드시 실패한다(그 실패 화면을 보는 것이 목적이라면 그것도 유효한 시험이다, F-06).
- 배포 대상이 각자 자기 계정으로 로그인할 거라면, **실제로 그 사람 계정 종류(Pro/Max/무료)를
  미리 확인**해 둘 것. 무료면 앱을 깔아 줘 봐야 아무 일도 안 일어난다.

### 1.2 설치 파일

- `release\YunOffice-Setup-0.20.0-x64.exe` (NSIS 설치본)
- `release\YunOffice-Portable-0.20.0-x64.exe` (포터블)
- **[코드]** 이름 규칙은 `package.json`의 `build.nsis.artifactName` / `build.portable.artifactName`,
  버전은 `package.json`의 `version`(현재 `0.20.0`).
- 새로 만들려면 `pnpm run build:win`. 이 명령은 `check:all`(논리 검사 + 화면 검사)을 먼저
  통과해야 진행된다 — **[코드]** `package.json` scripts.

### 1.3 파일을 옮기는 방법이 곧 시험의 일부다

SmartScreen 경고(2단계)는 파일에 **MOTW(Zone.Identifier)** 가 붙어 있어야 뜬다. 실제 배포와
같은 방법(메일·메신저·공유 링크에서 **브라우저로 다운로드**)으로 테스트 PC에 옮겨야
그 화면을 볼 수 있다. VM에 공유 폴더로 복사하거나 샌드박스에 클립보드로 붙여 넣으면
MOTW가 안 붙어 **경고가 안 뜰 수 있다.** — **[미확인]**(Windows 동작, 이번에 확인할 것)

옮긴 뒤 확인:

```powershell
Get-Item .\YunOffice-Setup-0.20.0-x64.exe -Stream Zone.Identifier
```

스트림이 있으면 SmartScreen 대상, `스트림을 찾을 수 없습니다` 계열 오류면 경고가 안 뜰 것이다.
그 경우 T-02는 **미확인**으로 남긴다(통과로 적지 않는다).

### 1.4 그 밖

- 인터넷 연결. F-02(설치 중 끊기)를 위해 **끊었다 붙일 수 있는** 연결일 것(VM 네트워크 어댑터,
  Wi-Fi 토글).
- 시간 40~70분(설치 대기가 대부분).
- 화면 캡처 도구를 미리 열어 둘 것(`Win+Shift+S`). **UAC 창이 떠 있는 동안에는 화면이
  잠기므로 캡처가 안 될 수 있다** — **[미확인]**. 안 되면 휴대폰으로 찍는다. 이 한 장(S10)은
  다시 만나기 어렵다.
- 계정 두 종류: **관리자 계정**과 **표준 사용자 계정**. 비개발자 회사 PC는 표준 사용자인
  경우가 많고, 그때 UAC는 "예/아니요"가 아니라 **관리자 암호를 묻는다** — **[미확인]**.
  표준 사용자에서 Python(burn 번들) 설치가 어떻게 끝나는지는 이번에 처음 보는 것이다.

### 2.1 Windows 11 가상머신 — 정답에 가장 가깝다

winget이 있으므로 **정상 경로를 그대로 밟는다.** 이 문서의 T-01~T-16과 F-01~F-05를 전부
소화할 수 있는 유일한 환경이다. 스냅샷을 찍어 두면 반복도 된다.

- 준비: 깨끗한 Win11 설치 → Windows 업데이트 1회(그래야 winget이 최신) → **스냅샷 `clean`**.
- 시험 1회마다 `clean`으로 되돌린다. 되돌리지 않으면 두 번째 시험은 "이미 깔린 PC" 시험이
  되어 버린다(= 개발 PC와 같아진다).
- winget이 실제로 있는지 먼저 확인: `winget --version`. 없으면(구형 이미지) 이 VM으로는
  winget 경로를 못 본다.

### 2.2 Windows 샌드박스 — **winget이 없다. 이 한계를 잊지 말 것**

이 PC(Win11 Pro)에서 바로 쓸 수 있고 닫으면 흔적 없이 사라져 **반복 시험에는 오히려 좋다.**
그러나 샌드박스 이미지에는 **App Installer(winget)가 없다.** — **[미확인]**(널리 알려진 사실이나
이번에 `winget --version`으로 직접 확인하고 기록할 것)

그래서 샌드박스에서 검증되는 것은 이렇다.

- **검증됨**: 마법사 자동 오픈 / 1단계 "없음" 목록 / 2단계 동의 화면에서
  `이 컴퓨터에서는 일부만 자동으로 설치할 수 있습니다. 나머지는 아래 [다운로드 페이지 열기]로
  직접 받아 주세요.` 문구 — **[코드]** `renderer/wizard.js` `renderConsent`.
  Claude Code는 `method:'script'`라 `available: true`이므로 **실제로 설치가 돈다**
  — **[코드]** `main.js:2608` `available: r.auto.method !== 'winget' || found.winget`.
  Python·Git 줄에는 [다운로드 페이지 열기] 버튼이 붙는다. 로그인·회사 만들기도 된다.
- **검증 안 됨**: winget 설치 자체 / UAC / `repairPortablePath` / python 훅 심층 검증 /
  Python·Git 관련 실패 화면 / SmartScreen(MOTW가 안 붙을 가능성).
- 주의: 샌드박스 사용자(`WDAGUtilityAccount`)는 **관리자**다 — **[미확인]**. 표준 사용자
  PC를 흉내 내지 못한다.
- 주의: 샌드박스는 닫는 순간 전부 사라진다. **스크린샷과 로그를 밖으로 빼기 전에 닫지 말 것.**

`.wsb` 예시(공유 폴더는 읽기 전용으로 두고, 설치본만 넣는다):

```xml
<Configuration>
  <MappedFolders>
    <MappedFolder>
      <HostFolder>C:\dev\2026\team-view\release</HostFolder>
      <ReadOnly>true</ReadOnly>
    </MappedFolder>
  </MappedFolders>
  <Networking>Enable</Networking>
</Configuration>
```

### 2.3 개발 PC — 쓰지 않는다

Python·Claude Code가 이미 있어 1·2단계가 통째로 건너뛰어진다. `%APPDATA%\team-view\config.json`을
지워 마법사를 다시 띄울 수는 있지만, 그래도 **설치는 여전히 일어나지 않는다.**
설치 경로 검증에는 쓸 수 없다.

### 2.4 반복 시험을 위한 되돌리기

VM은 스냅샷, 샌드박스는 재시작이 정답이다. 같은 PC에서 굳이 다시 하려면 아래를 지운다.

| 지울 것 | 왜 |
|---------|-----|
| `%APPDATA%\team-view\config.json` | `firstRunDone: true`가 여기 있다 — **[코드]** `main.js:2750-2752`, `configPath()` = `userData\config.json` |
| `%APPDATA%\team-view\` 전체 | `renderer.log`·`activity.log`·`chats\`·`runners.json`까지 초기화 |
| 브라우저(앱 내부) localStorage `teamview.firstRunDone` | 렌더러가 남기는 두 번째 표시 — **[코드]** `wizard.js` `DONE_KEY`. 앱 데이터 폴더를 통째로 지우면 같이 사라진다 |
| `내 문서\윤사무실\<이름>` | 5단계에서 만든 회사 폴더. 남아 있으면 `같은 이름의 폴더가 이미 있습니다` — **[코드]** `main.js:2694` |
| HKCU `Environment\Path`에 추가된 winget 포터블 폴더 | `persistUserPath`가 **덧붙이기만** 하고 지우지 않는다 — **[코드]** `install.js:335` |

## 3. 본 절차

각 항목은 **하는 일 / 통과 판정 / 여기서 멈추면 무슨 뜻 / 캡처**로 되어 있다.
멈춘 자리를 기록지에 그대로 옮겨 적는다(문구를 요약하지 말고 **그대로**).

### T-01 · 파일 받기 — 캡처 S1, S2

1. 실제 배포와 같은 방법으로 테스트 PC에서 파일을 받는다(브라우저 다운로드 권장, 1.3 참고).
2. 파일 이름이 `YunOffice-Setup-0.20.0-x64.exe`인지 본다.

- **통과**: 파일이 다운로드 폴더에 있고 이름 규칙이 맞다.
- **멈추면**: 브라우저가 "일반적으로 다운로드되지 않는 파일" 류로 막은 것이다. `설치안내.md`가
  `⋯` → **[유지]** 라고 안내하는 부분 — 그 메뉴가 실제로 그 이름인지 확인한다. **[미확인]**
- **캡처 S1**: 파일을 받는 화면(파일 이름이 보이게). **캡처 S2**: 차단된 줄 + `⋯` 메뉴가 펼쳐진 모습.
  차단이 안 일어나면 S2는 "재현 안 됨"으로 기록하고, `설치안내.md`의 그 문단을 조건부 표현으로
  바꿀지 판단한다.

### T-02 · SmartScreen 경고 — 캡처 S3, S4

1. 받은 파일을 더블클릭한다.
2. 파란 경고가 뜨면 **[추가 정보]** 를 누르고, 나타나는 **[실행]** 을 누른다.

- **통과**: `설치안내.md` 44~70줄이 적어 둔 것과 실제 화면이 같다 —
  (a) 처음에는 [실행] 버튼이 **없다**, (b) [추가 정보]를 누르면 앱 이름과 `게시자: 알 수 없는 게시자`가
  나오고 [실행]이 **생긴다**.
- **멈추면**: [실행]을 눌러도 아무 일이 없으면 백신이 파일을 이미 지웠을 수 있다(T-03).
- **[미확인]**: 문구·버튼 위치·"알 수 없는 게시자" 표기는 **전부 추정으로 적혀 있다.**
  Windows 버전에 따라 다르다. **실제 문구를 그대로 받아 적어** `설치안내.md`와 대조한다(6절 D-01).
- **캡처 S3**: [추가 정보] 누르기 **전**. **캡처 S4**: 누른 **뒤**([실행]이 생긴 상태).

  **이 문구가 화면에 제대로 뜨는지 자체가 검증 항목이다**(F-06).

### T-15 · 다시 켜도 유지되는가

앱을 완전히 종료하고 다시 켠다.

- **통과**: 마법사가 안 뜨고, ☰ › [설치 마법사 다시 열기]로 열면 1단계에서 세 항목이 전부
  `있음 · <버전>`으로 나온다. → **PATH 영속(`persistUserPath`)이 실제로 작동한다는 증거다.**
- **멈추면**: 다시 `없음`이 나오면 PATH가 프로세스에만 있었던 것이다(HKCU Path 확인).

### T-16 · 제거

- 설정 › 앱 › 설치된 앱에서 `윤사무실`을 찾아 제거한다.
- **확인**: 목록에 뜨는 이름이 정확히 무엇인지(**[미확인]**), 제거 후에도
  `내 문서\윤사무실\<이름>`이 남는지(`설치안내.md` 310줄의 주장).
- **확인**: `%APPDATA%\team-view\`가 남는지. 남는다면 `설치안내.md`에 한 줄 추가할 근거가 된다.
- 우리가 깐 Python·Git·Claude Code는 **제거되지 않는다**(당연하지만 문서에 그 말이 없다) → D-07.

## 4. 의도적 실패 시험

정상 경로만 보면 실패 화면은 영영 미검증으로 남는다. **아래는 선택이 아니다.**
VM 스냅샷을 쓰면 각각 깨끗한 상태에서 한 번씩 할 수 있다.

### F-01 · UAC에서 [아니요] 누르기 (VM 필수)

1. `clean` 스냅샷에서 시작 → 2단계 [설치 시작] → Python 차례의 UAC에서 **[아니요]**.
2. **기대(코드 기준)**: `installOne`이 `code !== 0`로 보고 오류 마지막 줄을 error로 싣는다
   (**[코드]** `install.js:744-754`). 마법사는 error에 `취소|cancel|1602|800704c7`가 있으면
   이렇게 적는다 — **[코드]** `wizard.js:740-743`:

   > `설치가 취소됐습니다. Python 없이도 앱은 켜지지만, 팀 활동을 화면에 기록하는 훅이 python으로 돕니다. 없으면 사무실이 조용합니다`
   > 버튼: [다시 시도] [건너뛰기]

3. **[위험] 여기가 이 시험의 핵심이다.** winget이 뱉는 마지막 줄이 저 정규식에 안 걸리면
   화면은 대신 `설치가 실패했습니다: <원문>. 공식 페이지에서 직접 받으실 수 있습니다.`를 띄운다.
   **실제로 어느 쪽이 나오는지, 그리고 winget의 마지막 줄 원문이 무엇인지 반드시 받아 적을 것.**
   (안 걸리면 `wizard.js`의 정규식에 그 코드/문구를 추가하는 것이 후속 작업이다.)
4. 이어서 **[다시 시도]** 를 누르고 이번엔 [예]를 눌러 정상 복구되는지도 본다.

### F-02 · 설치 도중 인터넷 끊기

1. [설치 시작] 직후(또는 Claude Code 차례에) VM 네트워크 어댑터를 끊는다.
2. **기대**: 오류 문구에 `인터넷|네트워크|network|offline|연결할 수 없|ENOTFOUND|ETIMEDOUT|EAI_AGAIN`
   중 하나가 들어 있으면 화면은 `인터넷에 연결되어 있지 않아 내려받을 수 없습니다.` + [다시 시도]
   — **[코드]** `wizard.js:744-746`.
3. **[위험] 반드시 확인할 것**: Claude Code는 winget이 아니라
   `powershell -NoProfile -NonInteractive -Command <psCommand>`로 돈다 — **[코드]** `install.js:624-625`.
   이 경로에는 `$ErrorActionPreference='Stop'` 접두가 **붙지 않는다**(그건 `runPowerShell`에만 있다).
   `Invoke-RestMethod`가 비종료 오류로 끝나면 **powershell이 exit 0으로 끝날 수 있고**, 그러면
   `install.js:753`의 `needsRestart = res.code === 0 && !res.timedOut`이 참이 되어 화면이
   **`설치는 됐는데 앱이 아직 못 찾고 있습니다. 앱을 한 번 다시 켜면 잡힙니다.` + [앱 다시 시작]** 를
   띄운다. 인터넷이 끊겼는데 재시작을 권하는, **사실이 아닌 화면**이다.
   → 실제로 어느 문구가 뜨는지 캡처하고, `needsRestart` 쪽이 뜨면 버그로 보고한다.
4. 네트워크를 다시 붙이고 [다시 시도] → 회복되는지 본다.

### F-03 · 설치 중에 창 닫았다가 ☰로 다시 열기

1. 설치가 도는 중에 마법사의 × 또는 Esc를 누른다.
2. **기대**: 곧바로 닫히지 않고 확인 상자가 뜬다 — **[코드]** `wizard.js` `requestClose`,
   `index.html:349-357`:

   > `지금 설치가 진행 중입니다. 창을 닫아도 설치는 뒤에서 계속되고, ☰의 [설치 마법사 다시 열기]로 돌아오면 진행 상황이 그대로 보입니다.`
   > 버튼: [계속 지켜보기] [창만 닫기]

3. [창만 닫기] → ☰ › **[설치 마법사 다시 열기]**.
4. **기대**: 동의 화면으로 되감기지 **않고** 진행 화면이 그대로 보이며 경과 시간이 이어진다
   — **[코드]** `wizard.js` `enterInstall`의 `if (installing)` 분기.
5. **추가로 볼 것(더 험한 경우)**: 설치 중에 **앱을 통째로 종료**했다가 다시 켠다.
   마법사 상태는 메모리에만 있으므로 사라진다. 그때 winget/설치 프로그램이 계속 도는지
   (작업 관리자에서 `winget`·`msiexec`·`python-3.13...exe` 확인), 다시 켠 앱이 무엇이라고 하는지
   기록한다. — **[미확인]**

### F-04 · 자동 설치를 못 하는 PC (샌드박스)

1. 샌드박스에서 설치본을 실행하고 2단계까지 간다.
2. **기대**: `이 컴퓨터에서는 일부만 자동으로 설치할 수 있습니다. 나머지는 아래
   [다운로드 페이지 열기]로 직접 받아 주세요.` + Python/Git 줄에 [다운로드 페이지 열기] 버튼,
   Claude Code는 자동 설치 가능 — **[코드]** `wizard.js` `renderConsent`/`canAutoFor`,
   `main.js:2608`.
3. [설치 시작] → Claude Code만 깔린다. 끝나면 남은 필수(Python)가 있으므로 버튼이
   `그래도 계속하기`가 되어야 한다.
4. [다운로드 페이지 열기]가 실제로 브라우저를 여는지 확인 — **[미확인]**(샌드박스에 브라우저가
   있는지 포함).
5. Python을 직접 깔고 **[설치했어요 — 다시 확인]** 을 눌러 본다. 이때 확인이 도는 동안
   `확인하는 중… (조금 걸릴 수 있습니다)`가 뜨고 버튼들이 **잠겨야** 한다
   — **[코드]** `wizard.js` `recheck`/`failBusy`.

### F-05 · 로그인을 건너뛰고 끝내기

3단계에서 로그인하지 않고 진행 → 6단계에
`Claude 로그인이 아직입니다 — 로그인해야 팀원이 일할 수 있습니다.`가 적히는지 확인
— **[코드]** `wizard.js` `enterDone`.

### F-06 · 플랜/크레딧 없는 계정으로 지시 보내기

무료 계정(또는 크레딧 소진 계정)으로 T-14를 하면 실패 라벨이 `결제·크레딧 문제` 또는
`토큰 사용량 한도`로 뜨는지 본다 — **[코드]** `main.js:3611-3617`.
**이 확인이 중요한 이유**: 비개발자에게 배포했을 때 가장 흔한 "아무 일도 안 일어나요"의
정체가 이것이다. 화면이 이유를 말해 주지 못하면 문의가 전부 개발자에게 온다.
