# 윤사무실 — AI 에이전트가 일하는 모습을 보는 데스크톱 앱

> Claude Code의 팀 에이전트가 **실제로 일하는 과정**을 픽셀 사무실로 시각화하는 Windows 앱.
> 터미널 로그 대신 사무실 한 칸을 본다.

---

## 한 줄 요약

`frontend-dev`가 호출되면 그 캐릭터가 자기 책상으로 **걸어가 앉아서 타이핑하고**, 무슨 파일을 만지는지 말풍선에 뜬다. 작업이 끝나면 자리에서 일어난다. 이 움직임은 연출이 아니라 **실제로 발생한 이벤트**다.

---

## 왜 만들었나

AI 코딩 에이전트에게 일을 시키면 터미널에 로그가 쏟아진다. 그런데 정작 알고 싶은 것은 로그에 잘 안 보인다.

| 알고 싶은 것 | 터미널에서 |
|---|---|
| 지금 **누가** 일하고 있나 | 출력이 뒤섞여 구분이 안 된다 |
| **뭘** 하는 중인가 | 도구 호출이 흘러가 버린다 |
| 아직 **도는 중**인가, 멈춘 건가 | 조용하면 알 수 없다 |
| **왜** 실패했나 | 스크롤을 한참 올려야 한다 |

여러 에이전트가 동시에 일할수록 심해진다. 로그는 시간순으로 한 줄씩 흐르는데, 실제 작업은 **여러 갈래로 동시에** 진행되기 때문이다.

**사무실 은유는 이 불일치를 해소한다.** 사람은 "누가 어디서 뭘 하는지"를 공간으로 파악하는 데 익숙하다. 다섯 명이 동시에 일해도 한눈에 들어온다.

---

## 핵심 원칙 — 가짜 활동을 만들지 않는다

시각화 도구가 빠지기 쉬운 함정이 있다. **보기 좋으라고 없는 움직임을 지어내는 것**이다. 그러면 화면이 예뻐지는 대신 신뢰할 수 없게 된다. "타이핑하고 있으니 잘 되고 있겠지"가 거짓이 되는 순간, 이 앱은 존재 이유를 잃는다.

그래서 규칙을 코드보다 먼저 정했다.

> **작업으로 보이는 움직임은 전부 실제 훅 이벤트에서 나온다.**
> 없는 작업을 지어내 자리로 걸어가 타이핑하는 캐릭터는 없다.

연출과 사실을 **화면에서도 구분한다**:

- 실제 작업 → 또렷한 말풍선 + 이름표에 활동 배지 (`✎ 수정 · 12s · 🛠 3`)
- 일이 없을 때의 커피·잡담·휴게실 이동 → **흐린 말풍선**, 배지 없음

이 원칙은 개발 내내 실제로 판단 기준이 됐다. 예를 들어 설치 진행 표시에서 타이머가 꺼지지 않아 **"설치 실패" 상자와 "내려받는 중 7분 경과"가 동시에** 뜨는 버그가 있었는데, 이건 단순한 UI 결함이 아니라 원칙 위반으로 분류해 우선 처리했다.

같은 원칙의 확장이 하나 더 있다.

> **확인하지 못한 것을 확인한 것처럼 말하지 않는다.**

설치가 성공(exit 0)으로 끝나도 그것만으로 "깔렸다"고 하지 않는다. `winget`은 포터블 패키지의 링크 생성이 실패해도 0을 주고, Python은 버전만 찍어 보면 Microsoft Store 스텁도 통과한다. 그래서 **실제로 실행해 보고** 결과가 남는지까지 확인한 뒤에야 성공이라고 말한다.

## 안전에 대한 설계

에이전트가 사용자 컴퓨터에서 파일을 고치고 명령을 실행한다. 그래서 **되돌릴 수 없는 동작을 구조적으로 막는 쪽**을 택했다.

| 위험 | 설계 |
|---|---|
| 팀원 해고 시 정의 파일 소실 | **삭제하지 않는다.** `.claude/team-fired/`로 옮긴다. 다시 고용하면 사람이 고쳐 둔 내용까지 그대로 복원된다 |
| 터미널 창 정리 중 사용자 창을 죽임 | 창 제목으로 찾지 않는다. **부모 PID + 명령줄이 모두 일치**할 때만 종료 |
| PATH 수정 중 기존 값 손실 | 추가 전용. 레지스트리 읽기·쓰기를 한 트랜잭션으로 처리 |
| 비밀값이 코드에 섞임 | 훅이 Edit/Write와 **Bash 명령 문자열까지** 검사. 한계도 문서에 명시 |

마지막 항목처럼 **막지 못하는 것을 문서에 적어 두는 것**도 설계의 일부로 봤다. 시크릿 가드 훅은 변수·인코딩·원격 파이프로 우회할 수 있고, 이미 있는 파일을 `git add`하는 경로는 검사하지 않는다. 이걸 숨기면 사용자가 훅을 과신하게 된다.
